# Integration contracts and operational limits

What the apps and the speech adapter actually do on top of [PROTOCOL.md](PROTOCOL.md), and where the limits are. The JSON fixtures under `Fixtures/` follow that document's examples and use reserved `.invalid` hosts and synthetic values.

## Backend credential format

Switchboard's signer uses `sbb1.<base64url JSON claims>.<base64url Ed25519 signature>`. The signature covers the exact ASCII prefix and encoded payload. It is not a JWT, and a JWT is not accepted.

Required signed claims are `v: 1`, `aud` (exact configured string), `profile: voicestack-mode-a-speech/1`, nonempty `call_id`, `binding`, `device_id`, `jti`, and integer `iat`/`exp`. The adapter bounds lifetime to 600 seconds, permits future `iat` by at most five seconds, and rejects expiry without grace. The example configuration issues 60-second credentials with audience `voicestack-mac-mode-a`. Apps treat credentials as opaque.

Each Realtime socket keeps its signed call binding and checks expiry on subsequent events; expiry closes the socket. HTTP synthesis checks authorization before upstream work and throughout streamed output. The adapter holds only the public key and never contacts Switchboard. `Fixtures/Speech-v1/switchboard-sbb1.json` was generated by the actual server Signer with a disposable test key and fixed clock; it is not a live credential.

## Response and renewal behavior

- `/me` includes `device_id` and `acknowledged`, used to reconcile an uncertain pairing acknowledgement. `/pair/ack` returns `paired` separately.
- `/backend-handoff` returns `{ "backend": ... }` only for the active owning device. Its idempotent replay returns a fresh credential.
- Native clients refresh an idle speech connection before expiry using a persisted operation identifier. Renewal preserves the existing text channel, call generation, pinned binding, captions and pending text turn. Old socket callbacks are fenced by a separate speech generation.
- The client waits until recording and committed transcription finish before rotating the speech socket. Each recording reserves 20 seconds before its credential expiry for recognition; a fresh 60-second handout therefore permits about 40 seconds of recording, with earlier automatic Send if time has already elapsed. The profile-wide maximum remains 90 seconds.
- Synthesis uses the current handout at execution time, renews when less than 40 seconds remain, and splits requests into at most 240 characters. Expired credentials still fail closed; the app does not replay an uncertain text turn.
- Phone-policy behavior while suspended, expired availability leases, and Focus need physical-device acceptance. The phone republishes in the foreground and on incoming signals; it cannot promise continuous background execution.

## Audio behavior and limits

Input is mono 24 kHz signed PCM16 little-endian, at most 100 ms per append and 90 seconds per committed turn. The app has a bounded capture queue and ends the current recording near the turn limit. Backpressure fails the call's audio path rather than dropping frames silently. A windowed-sinc low-pass converter retains phase, filter history and odd-byte state across the adapter's appends; final drain happens once. Parakeet is requested with `?partials=1`. Standard clients receive only stable, whole-word additive deltas shared by successive hypotheses, with the canonical final replacing the preview. Native clients opt into full replacement previews with the `X-VoiceStack-Live-Preview: snapshots-v1` WebSocket header. Only opted-in sockets receive `voicestack.input_audio_transcription.preview` (`item_id`, `content_index`, `text`). These events replace display text; they never admit a text turn. This optional adapter extension preserves the normal profile for clients/backends without it and does not mislabel replacement snapshots as additive deltas. Only normal final closure completes recognition; abnormal closure fails.

Readiness requests WAV from Breeze to verify format metadata, data bounds, byte rate, channels and sample width. PCM synthesis then streams from the same local service, requiring `Content-Type: audio/pcm`, `X-Sample-Rate: 24000` and `X-Sample-Format: s16le` on every response. An optional channel header must be 1; the installed gateway’s mono contract is checked by the WAV readiness probe. Odd-byte chunk boundaries are retained and incomplete final samples fail. The adapter forwards bounded chunks and the app schedules them progressively. Reply deltas release complete prose segments in order; `reply.done` flushes only the remaining text. WAV requests retain whole-file validation. Physical latency and route continuity remain unproven.

HTTPS/WSS uses system trust without certificate bypass. Redirects, URL credentials and non-profile query parameters are refused. Tailnet DNS, TLS certificates and ACLs must be configured at deployment; an HTTPS URL by itself does not prove tailnet-only reachability. `scripts/install-mac-adapter.py` can run the adapter as a user LaunchAgent from a local release copy. Switchboard is meant to sit behind a private Tailscale Serve route; no Funnel route is used.

## Focus platform limit

The implementation uses Apple's public `INFocusStatusCenter`, requests permission, and reads `focusStatus.isFocused`. Visibility depends on authorization and the app's relationship to the current Focus configuration. There is no claim that this is an unrestricted global Focus monitor or that a suspended app receives every state change. Unknown status is restrictive. The exact behavior with the user's signed app, permissions, lock screen and Focus configuration must be tested on a real device before relying on the cross-device Focus rule.

Primary reference: [Apple INFocusStatusCenter](https://developer.apple.com/documentation/Intents/INFocusStatusCenter).

## Native listening and unsent discard

Power expands the Mac card immediately. Microphone capture starts only after explicit call start/acceptance, text and speech readiness, OS permission and platform audio activation. The adaptive 20 ms pause detector ends recognition after the selected quiet interval. Reply synthesis is serialized; automatic listening resumes after pending synthesis and actual playback have drained. This is half-duplex; full echo-cancelled barge-in is not claimed.

Recognition commit and text delivery are separate. Discard stays available during capture, transcription and any final-caption review delay. It cancels capture and queued delivery, closes the old recognition socket, clears unsent captions and opens a fresh speech transport. Both call generation and speech epoch fence old callbacks. It never cancels a turn that was already submitted.

If automatic recognition delivers new words only in its final result, those words remain visible for at least 1.5 seconds before submission. Time already visible in a matching live snapshot counts toward that interval; punctuation-only changes do not add another wait. Explicit Send bypasses this review delay. This is a bounded safeguard for slow final recognition, not a claim of parity with the earlier client's composer: multi-utterance merging, mid-sentence holds and full barge-in remain unported.
